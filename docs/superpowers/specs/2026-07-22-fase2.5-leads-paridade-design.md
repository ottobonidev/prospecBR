# Fase 2.5 — Paridade do módulo Leads com o sistema real

## Contexto

O walkthrough documentado em `docs/superpowers/specs/2026-07-22-conectaobras-sistema-real.md`
mostrou que o card de obra, os filtros avançados e a busca de cidade do clone (Fase 2) são muito
mais rasos que o sistema real. Esta fase fecha essa distância no módulo Leads antes de avançar
para CRM (Fase 3).

Escopo fechado com o usuário: paridade de **dados e filtros** agora; as ações de card que
dependem do funil de vendas (agendar, etiquetar/acompanhar) ficam para a Fase 3 (CRM), pois no
sistema real elas escrevem nas mesmas tabelas do CRM. Favoritar e ocultar/excluir são simples o
bastante para entrar já nesta fase.

## O que entra

1. **Schema `Obra` ampliado** com os campos que aparecem no card real: responsável (pode diferir
   do proprietário), categoria, subcategoria, tipo de obra, tipo de área, zona, destinação,
   tipo de responsável (PF/PJ), área total (distinta da metragem quando a obra é "Existente"),
   endereço completo formatado, complemento.
2. **Dois campos calculados e persistidos** — valor de investimento e previsão de término — que
   não vêm da fonte (CNO não informa nenhum dos dois): calculados por uma função pura reutilizada
   pelo seed e pela futura ingestão, e armazenados como colunas normais (não recalculados a cada
   leitura) para permitir filtro/ordenação simples.
3. **Filtros avançados completos**: categoria, subcategoria, tipo de obra, tipo de área, zona,
   destinação, tipo de responsável, faixa de metragem (8 faixas fixas iguais às do sistema real),
   intervalo de data de início. Situação (status) já existia.
4. **Cidade via API do IBGE** (`servicodados.ibge.gov.br`, pública e gratuita) em vez de texto
   livre — autocomplete de município por UF, igual ao sistema real.
5. **Paginação numérica** com contagem total, substituindo a única página atual.
6. **Favoritar** e **Ocultar** (equivalente ao ícone de lixeira do card real, que remove a obra
   da listagem daquele usuário sem apagar o registro global) — persistidos por usuário.
7. **Card de obra completo**: os 14 campos do card real, incluindo os dois ícones de ação que
   ainda não têm função (calendário/agendar, etiqueta/acompanhar) desenhados como desabilitados
   com tooltip "Disponível no CRM" — sinalizando ao usuário que a função existe e chega na
   próxima fase, no mesmo espírito do "Em breve" que o próprio sistema real usa.

## Fora de escopo (explícito)

- Ícones de enriquecimento do proprietário (consulta de dados, WhatsApp, busca Google) — exigem
  fonte de dados de contato que não temos; ficam sem função nesta fase, mas visíveis (cinza).
  Isso é diferente da omissão total: o card real sempre mostra esses ícones, então nosso card
  também mostra, só que inertes por enquanto.
- Deduplicação de obras (o sistema real tem duplicatas visíveis — não vamos reproduzir o bug,
  mas também não vamos construir um deduplicador agora; a fonte real via Base dos Dados decide
  isso quando a ingestão entrar em produção).
- Busca global CNO, Obras CAU, Empresas PJ — sub-abas próprias, ficam para fases futuras
  dedicadas (o Dashboard e o CRM vêm antes na priorização).

## Arquitetura

### Schema (`packages/db/prisma/schema.prisma`)

Novos enums: `CategoriaObra`, `SubcategoriaObra`, `TipoObra`, `TipoArea`, `Zona`,
`DestinacaoObra`, `TipoResponsavel` — valores exatamente como capturados no walkthrough (seção 3.1
do mapa do sistema real).

Novos campos em `Obra`: `responsavelNome String?` (default = mesmo texto do proprietário quando
ausente), `categoria`, `subcategoria`, `tipoObra`, `tipoArea`, `zona`, `destinacao`,
`tipoResponsavel`, `areaTotal Float?`, `enderecoCompleto String?`, `complemento String?`,
`valorInvestimentoCentavos Int?`, `previsaoTermino DateTime?`.

Novos models: `ObraFavorito` (contaId, usuarioId, obraId, criadoEm; `@@unique([usuarioId, obraId])`)
e `ObraOculta` (mesma forma) — ambos por usuário, não por obra global (duas contas podem ter
opiniões diferentes sobre a mesma obra, que é dado compartilhado).

### Cálculo (`apps/web/lib/calculoObra.ts`)

Funções puras, sem I/O:
- `calcularValorInvestimentoCentavos(areaConstruida: number): number` — `areaConstruida * 225400`
  (R$ 2.254,00/m², a constante observada em todos os registros reais do walkthrough).
- `calcularPrevisaoTermino(dataInicio: Date, areaConstruida: number): Date` — prazo em meses
  proporcional à área, com piso de 6 e teto de 36 meses (`clamp(areaConstruida / 50, 6, 36)`),
  somado à data de início.

Usadas pelo script de seed agora; serão as mesmas usadas pelo worker de ingestão quando a Fase 2
(BigQuery) for religada com fonte real.

### Busca (`apps/web/lib/services/leads.ts`)

`BuscarObrasInput` ganha: `categoria?`, `subcategoria?[]`, `tipoObra?[]`, `tipoArea?[]`, `zona?[]`,
`destinacao?[]`, `tipoResponsavel?[]`, `metragemFaixa?` (uma das 8 faixas fixas, mapeada para
`areaConstruida: { gte, lte }` no `where`), `dataInicioDe?`, `dataInicioAte?`.

### IBGE (`apps/web/app/api/ibge/municipios/route.ts`)

`GET ?uf=PR` → proxy para `https://servicodados.ibge.gov.br/api/v1/localidades/estados/{uf}/municipios`,
resposta reduzida a `[{ nome: string }]`, cache em memória de processo por 24h por UF (a lista de
municípios não muda). Sem autenticação, sem custo, sem crédito consumido (não é busca de lead).

### Favoritar / Ocultar (`apps/web/lib/services/obraFavoritos.ts`)

`alternarFavorito(prisma, { contaId, usuarioId, obraId })` — toggle via upsert/delete.
`ocultarObra(prisma, { usuarioId, obraId })` — cria `ObraOculta`; `buscarObras` passa a excluir
obras ocultas do usuário atual via `NOT IN` subquery quando `usuarioId` é informado.

### UI

- `leads-search-form.tsx` ganha modal de filtros avançados (mesmo padrão visual do sistema real:
  seções com `Selecione categoria`, etc.), cidade como combobox alimentado por `/api/ibge/municipios`,
  paginação numérica.
- Card de obra reescrito com os 14 campos e 4 ícones de ação (favoritar funcional, ocultar
  funcional, agendar/etiquetar desabilitados com tooltip).
